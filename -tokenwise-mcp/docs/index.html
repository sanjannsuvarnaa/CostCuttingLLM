Cut your LLM token costs

tokenwise-mcp is an MCP server and library that compresses prompts, summarizes conversation history, retrieves only the document chunks you need, and plans Anthropic prompt-cache breakpoints — so every turn of your agent loop costs less.

Installation

Requires Node.js 18+. Use it as an MCP server in Claude Code / Claude Desktop, or import it directly as a library.

Add to Claude Code

npm install -g tokenwise-mcp
claude mcp add tokenwise tokenwise-mcp

Or run it on demand with npx — no global install:

claude mcp add tokenwise -- npx -y tokenwise-mcp

Or add it manually to ~/.claude/claude_desktop_config.json:

{
  "mcpServers": {
    "tokenwise": {
      "command": "tokenwise-mcp"
    }
  }
}

Use as a library

npm install tokenwise-mcp
import {
  compressPrompt,
  summarizeContext,
  chunkDocument,
  estimateTokens,
  planPromptCaching,
  planCacheBreakpoints,
  countTokens,
} from "tokenwise-mcp";

// Compress a verbose prompt
const { compressed, tokensSaved } = compressPrompt(myPrompt, "high");

// Retrieve only the chunks relevant to a query
const { chunks } = chunkDocument(bigDoc, "authentication flow", 3, 500);

// Plan prompt-cache breakpoints for an agent loop request
const plan = planCacheBreakpoints({
  system: systemPrompt,
  tools: toolDefinitions,
  messages: conversation,
  model: "claude-3-5-sonnet",
});
console.log(plan.estimatedSavingsPercent, plan.pricingExact, plan.notes);

// Apply the returned system/tools/messages directly in your
// Anthropic SDK request - they're already annotated with cache_control.

compress_prompt 10–30% saved

Compresses a prompt by removing filler phrases and verbose wording. Set aggressiveness to low, medium, or high.

Example 
{
  "tool": "compress_prompt",
  "arguments": {
    "prompt": "Sure! I'd be happy to help. In order to solve this, due to the fact that we need to...",
    "aggressiveness": "high"
  }
}
{
  "original": "Sure! I'd be happy to help. In order to...",
  "compressed": "to solve this, because we need to...",
  "tokensSaved": 12,
  "percentSaved": 28
}

summarize_context 20–40% saved

Summarizes conversation history, keeping the most recent messages verbatim and compressing older ones down to a token budget.

Example 
{
  "tool": "summarize_context",
  "arguments": {
    "messages": [
      {"role": "user", "content": "...long earlier message..."},
      {"role": "assistant", "content": "...long response..."},
      {"role": "user", "content": "What about performance?"},
      {"role": "assistant", "content": "Performance depends on..."}
    ],
    "maxTokens": 2000
  }
}

chunk_document 70–90% saved

Splits a large document and returns only the chunks most relevant to a query — instead of dumping the whole document into context.

Example 
{
  "tool": "chunk_document",
  "arguments": {
    "document": "...10,000 word document...",
    "query": "authentication flow",
    "maxChunks": 3,
    "chunkSize": 500
  }
}

estimate_tokens

Counts tokens in text and estimates cost for a given model. Exact for OpenAI models (via tiktoken); approximate for Claude and other models where no public tokenizer exists.

Example 
{
  "tool": "estimate_tokens",
  "arguments": {
    "text": "Your prompt here",
    "model": "claude-3-5-sonnet"
  }
}
{
  "tokenCount": 14,
  "tokenCountExact": false,
  "tokenizer": "cl100k_base (approximate)",
  "estimatedCostUSD": 0.000042,
  "model": "claude-3-5-sonnet",
  "pricingExact": true
}

optimize_system_prompt 15–40% saved

Converts verbose prose instructions into concise bullet points, preserving meaning while cutting tokens.

Example 
{
  "tool": "optimize_system_prompt",
  "arguments": {
    "systemPrompt": "You are a helpful assistant. It is important to note that you should always be concise. Please be advised that you must not share private data..."
  }
}

cache_context 100% on repeats

Stores reusable context (project rules, persona, boilerplate) once, so you don't have to re-send it every session. Persists at ~/.tokenwise/cache/<namespace>.json.

Example 
{ "tool": "cache_context", "arguments": { "action": "set", "key": "project-rules", "value": "Always use TypeScript. No any types." } }
{ "tool": "cache_context", "arguments": { "action": "get", "key": "project-rules" } }
{ "tool": "cache_context", "arguments": { "action": "list", "key": "" } }
{ "tool": "cache_context", "arguments": { "action": "delete", "key": "project-rules" } }

plan_prompt_caching 50–65% in agent loops

The headline feature. Places Anthropic cache_control breakpoints on your system prompt, tool definitions, and stable conversation prefixes, then returns them ready to send to the Anthropic API as-is.

set_proactive_mode

Saves the user's one-time yes/no decision on whether Claude should use tokenwise tools automatically, without being asked. Called by Claude itself after asking you — see Proactive Mode for the full setup/disable flow.

Example 
{ "tool": "set_proactive_mode", "arguments": { "enabled": true } }
{ "success": true, "enabled": true, "message": "Proactive mode enabled. tokenwise tools will be used automatically when helpful, without being asked, until told otherwise." }

Proactive Mode

By default Claude only calls tokenwise tools when you ask. Opt in once to have it decide on its own when a tool would help.

Turning it on

npx tokenwise-mcp setup

This merges a SessionStart hook into ~/.claude/settings.json — it won't touch unrelated settings, and running it again is a no-op if already installed. Restart Claude Code, or open /hooks once, for it to take effect.

From the next session on, Claude will ask once whether it should use tokenwise tools automatically (chunking large docs, caching repeated context, warning before pasting huge text, etc.) instead of waiting to be asked. Your answer is saved to ~/.tokenwise/proactive/ and is not asked again.

Turning it off

  • Pause it, keep the hook installed — tell Claude "stop using tokenwise automatically." It calls set_proactive_mode with enabled: false; future sessions see the tools are available but won't use them unless asked. Ask Claude to turn it back on any time to re-enable.
  • Remove the hook entirely — run npx tokenwise-mcp uninstall. This deletes the SessionStart hook entry (leaving every other setting untouched) and restores the original explicit-only behavior. Restart Claude Code, or open /hooks once, for it to take effect.
Your yes/no answer stays saved in ~/.tokenwise/proactive/ even after uninstall — delete that file too if you want a future setup to ask the question again from scratch. Skipping setup altogether keeps tokenwise fully explicit-only, exactly as before this feature existed.

Dashboard

A small local HTTP server with no external dependencies. View daily token-savings as a chart, with a per-tool breakdown for today.

tokenwise-dashboard       # or: npx -y tokenwise-dashboard

Then open http://localhost:4317.

  • TOKENWISE_DASHBOARD_PORT — change the port (default 4317)
  • TOKENWISE_NAMESPACE — view a different namespace's usage
The dashboard reads ~/.tokenwise/usage/<namespace>.json directly — any MCP session on the same machine that calls a savings tool (compress_prompt, summarize_context, chunk_document, optimize_system_prompt, plan_prompt_caching) will update the same file. Refresh the page to see new totals — it doesn't auto-poll.

Licensing

Currently in free beta — license enforcement is temporarily disabled while feedback is gathered, so all tools and the dashboard are unlocked regardless of trial status. The mechanics below remain active and will be enforced in a future release.

tokenwise-mcp is free to use for a 14-day trial (all tools, starting from first run — tracked in ~/.tokenwise/trial.json). After the trial, all tools (including the dashboard) require a valid license key.

Licenses are perpetual and fully offline: a signed token containing your email and tier, verified locally against an embedded public key. No server, no phone-home, no recurring fee.

Activating a key

{ "tool": "activate_license", "arguments": { "key": "TRMCP-...." } }

This verifies the key and saves it to ~/.tokenwise/license.key. Alternatively, set the TOKENWISE_LICENSE_KEY environment variable, or write the key to that file directly. Run activate_license with no key to check current trial/license status at any time.
